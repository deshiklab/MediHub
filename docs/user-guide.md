# MediHub dashboard user guide

This guide describes the current **synthetic-only dashboard and device-management workbench**. It is an operator guide for local development and demonstrations—not a clinical, production, or facility-integration manual. The workbench does not connect to physical devices, external services, an EMR/EMS, or a patient record.

> **Safety boundary:** Use generated demo values only. Do not enter or import personal information, patient identifiers, real measurements, clinical notes, credentials, tokens, production URLs, or other secrets. A green/healthy status or passing synthetic test is not evidence of clinical readiness, facility approval, security compliance, or production availability.

## 1. Start the dashboard

Use Python 3.11 or newer. From the repository root, install the development dependencies if needed and start the app:

```bash
python -m pip install -e ".[dev]"
python -m medihub dashboard --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000`. For a hosted browser preview, bind to `0.0.0.0` instead of `127.0.0.1`; do not expose this unauthenticated demo as a production service.

The interface language selector in the header switches between **English** and **বাংলা**. The preference is saved in that browser's local storage. No translation service or font download is called. Technical identifiers, protocol names, metric codes, and machine-generated error codes may remain in English so they continue to match the underlying system.

## 2. Pages at a glance

| Page | Route | What it shows |
| --- | --- | --- |
| Operations | `/` or `/operations` | Synthetic source/receiver status, event and outbox metrics, recent synthetic events, delivery attempts, policy holds, and curated audit metadata. |
| Device management | `/devices` | In-memory simulator registrations and controls, an illustrative device-category catalog, non-secret API drafts, per-device flow and mapping previews, and CSV/JSON export. |
| Data mapping | `/mappings` | Inactive mapping drafts, exact-match previews, synthetic golden test vectors, and in-memory revision history. |
| EMR / EMS APIs | `/api-setup` | Locked planning cards for future EMR/FHIR and EMS/HL7 discovery plus local synthetic receiver drills. No external API can be configured here. |
| Help / user guide | `/help` | An in-app explanation of the demo boundary, workflows, safety, Bangladesh planning, and common issues. |

The pages share the same shell and language preference. Use the navigation tabs to move between them. The operations overview refreshes its synthetic snapshot automatically; device-flow details refresh periodically while that page is open.

## 3. Understand the operations overview

The dashboard's event values are generated by the local simulator. The in-process test receiver is a demo component, not a network destination.

1. **Source and receiver cards** show the status of the local synthetic adapter and test receiver. They do not report the state of a real device or facility.
2. **Metric cards** summarize stored synthetic events, duplicate event IDs, outbox delivery attempts, test acknowledgements, pending work, and policy holds.
3. **Recent synthetic events** show a curated subset of fields. Full payloads and patient context are not displayed.
4. **Outbox activity** shows delivery lifecycle metadata. Choose **Inspect** to review the allowlisted detail and attempts for an event. If enabled, **Retry terminal failure** requests an explicit local synthetic replay using the stable event ID.
5. **Durable policy holds** show stable reason codes. The dashboard does not provide an automatic policy override.
6. **Synthetic audit activity** shows curated system actions and reason codes, not payloads or actor identifiers.

“Durable” in a panel title describes the demo's local event-store behavior while it is running; it does not mean the dashboard is a production retention or compliance system. Runtime data is bounded and in-memory for this dashboard process.

## 4. Work with demo devices

### Register and control a simulator

1. Open **Device management** and choose **Register simulator**. The new row is an in-memory synthetic simulator; no hardware discovery occurs.
2. Use **View details** to select a simulator and show its status, local API draft, shared mapping preview, and flow.
3. **Set active** allows that simulator to emit local demo samples. **Set inactive** prevents further samples from that simulator. Neither action sends a command to hardware.
4. Choose **Emit sample** to exercise the local pipeline. The per-device flow summarizes the source, MediHub ingestion, outbox, and in-process test destination. Refresh the flow if you want an immediate update.
5. The device catalog contains illustrative categories, not a compatibility list. **Use in draft** selects an example class in the non-secret draft form; it does not discover, validate, or connect a device.

Registrations and settings are temporary and reset when the server restarts. The per-device mapping panel is a shared, inactive synthetic mapping view—not a persisted assignment for each physical device.

### Prepare a non-secret API discovery draft

Choose a simulator, then set an example device class, candidate transport, payload profile, and poll interval. **Save local draft** keeps these values only in the current browser page session. Endpoint URLs, authentication, passwords, tokens, certificates, and live activation are deliberately not collected. The disabled **Activate connector** button is informational; it cannot turn on a connector.

A real device integration would first require exact manufacturer/model/firmware and protocol discovery, an authorized source specification, facility approval, and a separately reviewed connector design. Nothing in the illustrative catalog should be treated as a support claim.

### Export synthetic rows

Choose CSV or JSON and use **Export selected device** to download up to 12 recent curated synthetic rows for the selected simulator. The export is generated in the browser from the current synthetic dashboard snapshot. It does not call an export service or send data to an external destination. Keep it as a test artifact and do not add real data.

## 5. Review and test mapping drafts

Mapping rules use exact source metric and unit codes. A rule can preserve the value (identity) or apply the configured linear scale and offset, with a specified decimal precision. The preview is synthetic-only and does not infer a source unit or choose a rule for you.

1. In **Data mapping**, review the current draft's source code/unit and normalized code/unit entries.
2. Add a rule with a unique exact source metric/unit and a normalized example code/unit. The example code system is fixed to `example.invalid` and the unit vocabulary to `UCUM` in this demo.
3. Choose a simulator and enter a synthetic source code, unit, and scalar value in **Preview mapping**. A match should be exact. An unmatched input should remain unmapped; do not guess a clinical interpretation.
4. Add synthetic **Golden test vectors** with expected outputs. Run the mapping tests after editing a draft. Test results are tied to the mapping version; a changed draft can make prior results stale.
5. Use **Revision history** to compare an earlier snapshot or restore it as a new inactive draft. The in-memory history is capped at 100 revisions.

Mapping activation is disabled. Passing test vectors verifies only the coded demo examples; it is not clinical validation, terminology approval, device certification, or authorization to write to a real system. See [the synthetic mapping workbench notes](SYNTHETIC_MAPPING_WORKBENCH.md) for additional implementation boundaries.

## 6. Understand the EMR / EMS API page

The API page is a planning surface, not a connector configuration page:

- **FHIR R4 / EMR** is a future planning target. The card is disconnected; there is no base-URL entry, credential store, network sender, or live activation.
- **HL7 v2 / interface engine / EMS** is also a future planning target. Host/port and transport/ACK settings are not collected, and the card is disconnected.
- The available receiver and fault controls exercise only the in-process synthetic sink. A drill may demonstrate a retryable outcome, rejection, or lost acknowledgement, but it does not test a real receiving system.

Before a separate real integration is designed, the responsible facility and authorized teams must agree on interface contracts, resource/message profiles, patient-context rules, identifiers, acknowledgements, idempotency and retry behavior, security and privacy controls, approved test endpoints, monitoring, support, and change ownership. Do not use this dashboard to enter those details.

## 7. Privacy, security, and operating limits

- Use only simulator-generated arbitrary values. Never put real patient or device information into the app, test fixtures, screenshots, exports, logs, or source control.
- Do not paste secrets into the interface. There is no secrets manager or external connection in this workbench.
- This dashboard has no authenticated operator roles, facility/site scoping, production-grade durable configuration, secure deployment controls, or tamper-evident audit trail. Do not expose it as a production control plane.
- Local storage is used only for the selected language preference. Device API drafts are held in a JavaScript page-session map; simulator and mapping records are held in memory by the local application. Restarting the server clears server-side demo setup and its runtime feed.
- A CSV/JSON file downloaded by the browser remains under the user's local download and file-management controls. Handle it as a test artifact.
- The project's broader event persistence/replay paths have different storage behavior and may persist input JSON. Do not pass real data to those paths; follow the README's synthetic-only guidance.

## 8. Bangladesh deployment-readiness checklist

Bangladesh is a required MediHub deployment context, but this synthetic preview is **not ready for use in a Bangladeshi health facility**. A future proposal should not proceed until a facility-specific discovery and approval process addresses at least:

- named clinical, operational, technical, privacy, security, and vendor owners at each participating facility;
- exact device models, firmware, communication protocols, source terminology, units, calibration/quality processes, and support responsibility;
- the target EMR/EMS interface contract, message/resource profiles, patient association and identity rules, ACK/idempotency/retry semantics, and an approved synthetic test environment;
- applicable Bangladesh laws, regulator directions, facility policies, consent and access expectations, data-residency/hosting choices, retention, incident response, and cross-border processing, assessed by qualified local stakeholders;
- connectivity limits and operating conditions at the actual facilities, including power/network interruption and a support/escalation path;
- English and Bengali usability, script rendering, accessibility, operator training, and safe handling of language-specific names and terminology;
- an independent security/privacy assessment, threat model, authentication and role design, encryption, secrets management, logging/retention, backup/recovery, and deployment hardening;
- a staged pilot plan with facility-approved synthetic tests, clinical safety review, measurable acceptance criteria, rollback, and explicit authorization before any live data or connection is considered.

This list is a planning aid—not legal advice, a statement of local compliance, a Bangladesh Core FHIR claim, or authorization to deploy. Country-specific requirements and facility agreements must be verified for the intended deployment.

## 9. Troubleshooting

| Symptom | Check |
| --- | --- |
| No sample appears | Register and activate a simulator, select it, then emit a sample. Refresh the device flow. |
| A mapping preview does not match | Confirm the source metric **and** unit exactly match the draft; verify the selected simulator. Add a synthetic test vector for the intended case. |
| A delivery is queued or failed | Inspect the delivery and its attempt history. Use a manual retry only when the button is enabled; this remains a local synthetic replay. |
| A device or mapping change vanished | The setup is temporary. Server-side registrations, mapping drafts, revisions, and runtime feed reset when the server restarts; API drafts also disappear when the page session ends. |
| The page does not update | Check the local server is running and reload the page. The operations page refreshes automatically when connected. |
| Bengali text looks different across machines | Font availability and browser rendering vary. The UI declares Bengali fonts as fallbacks and does not download a font; verify a Bengali-capable local font and browser on each target device. |
| EMR/EMS controls cannot be used | This is intentional. The API cards are locked plans, not a hidden connection setup. |

## 10. Glossary

- **Synthetic data:** generated demo values that do not represent a person, patient, physical device, or clinical measurement.
- **Simulator:** an in-process demo source that can emit those generated values.
- **Outbox:** a local record of a delivery intent and attempts before/while handing it to a receiver. Here the receiver is in the same process.
- **Idempotency:** recognizing a repeated stable event ID so a duplicate send does not create an extra unique test receipt.
- **Mapping draft:** an inactive temporary exact-match conversion rule for synthetic source code/unit to an example normalized code/unit.
- **FHIR R4 / HL7 v2:** standards named as future interface-planning targets; neither is connected by this dashboard.

এই নির্দেশিকা বর্তমান **শুধু সিন্থেটিক ড্যাশবোর্ড ও ডিভাইস-ব্যবস্থাপনা ওয়ার্কবেঞ্চ** সম্পর্কে। এটি স্থানীয় উন্নয়ন ও ডেমোর জন্য অপারেটর নির্দেশিকা—ক্লিনিক্যাল, উৎপাদন বা কোনো স্বাস্থ্যপ্রতিষ্ঠানে ইন্টিগ্রেশন পরিচালনার নির্দেশিকা নয়। ওয়ার্কবেঞ্চ বাস্তব ডিভাইস, বাহ্যিক সেবা, EMR/EMS বা রোগীর রেকর্ডে সংযোগ করে না।

> **নিরাপত্তার সীমা:** শুধু সিমুলেটরে তৈরি ডেমো মান ব্যবহার করুন। ব্যক্তিগত তথ্য, রোগীর শনাক্তকারী, বাস্তব পরিমাপ, ক্লিনিক্যাল নোট, পরিচয়-প্রমাণ, টোকেন, উৎপাদন URL বা গোপন তথ্য দেবেন না। সবুজ/স্বাভাবিক অবস্থা বা সিন্থেটিক পরীক্ষা পাস হওয়া ক্লিনিক্যাল প্রস্তুতি, প্রতিষ্ঠানের অনুমোদন, নিরাপত্তা-সম্মতি বা উৎপাদন সক্ষমতার প্রমাণ নয়।

## ১. ড্যাশবোর্ড চালু করুন

Python 3.11 বা তার পরের সংস্করণ ব্যবহার করুন। রিপোজিটরির মূল ফোল্ডার থেকে প্রয়োজনীয় প্যাকেজ ইনস্টল করে অ্যাপ চালু করুন:

```bash
python -m pip install -e ".[dev]"
python -m medihub dashboard --host 127.0.0.1 --port 8000
```

`http://127.0.0.1:8000` খুলুন। হোস্ট করা ব্রাউজার প্রিভিউতে চালাতে `127.0.0.1`-এর বদলে `0.0.0.0`-এ bind করুন; প্রমাণীকরণবিহীন এই ডেমোকে উৎপাদন সেবা হিসেবে প্রকাশ করবেন না।

হেডারের ভাষা-নির্বাচক থেকে **English** বা **বাংলা** বেছে নেওয়া যায়। পছন্দটি ওই ব্রাউজারের local storage-এ রাখা হয়। কোনো অনুবাদ সেবা বা ফন্ট ডাউনলোড হয় না। প্রযুক্তিগত শনাক্তকারী, প্রোটোকলের নাম, মেট্রিক কোড এবং সিস্টেম-তৈরি ত্রুটি কোড মূল ইংরেজিতে থাকতে পারে, যাতে সেগুলো সিস্টেমের মানের সঙ্গে মেলে।

## ৩. কার্যক্রমের সারাংশ বুঝুন

ড্যাশবোর্ডের ইভেন্ট মান স্থানীয় সিমুলেটর তৈরি করে। প্রসেসের ভেতরের পরীক্ষামূলক রিসিভার একটি ডেমো উপাদান—এটি নেটওয়ার্ক গন্তব্য নয়।

১. **উৎস ও রিসিভার কার্ড** স্থানীয় সিন্থেটিক অ্যাডাপ্টার ও পরীক্ষামূলক রিসিভারের অবস্থা দেখায়; বাস্তব ডিভাইস বা প্রতিষ্ঠানের অবস্থা নয়।
২. **মেট্রিক কার্ড** সংরক্ষিত সিন্থেটিক ইভেন্ট, ডুপ্লিকেট ইভেন্ট ID, আউটবক্স ডেলিভারির চেষ্টা, পরীক্ষামূলক স্বীকৃতি, অপেক্ষমাণ কাজ ও নীতি-হোল্ডের সারাংশ দেয়।
৩. **সাম্প্রতিক সিন্থেটিক ইভেন্টে** বাছাই করা কিছু ক্ষেত্র দেখা যায়; পূর্ণ পেলোড বা রোগীর প্রসঙ্গ দেখানো হয় না।
৪. **আউটবক্স কার্যক্রমে** ডেলিভারি-জীবনচক্রের মেটাডেটা দেখা যায়। কোনো ইভেন্টের অনুমোদিত বিবরণ ও চেষ্টা দেখতে **বিস্তারিত দেখুন** নির্বাচন করুন। চালু থাকলে **চূড়ান্ত ব্যর্থতার পুনঃচেষ্টা** স্থিতিশীল ইভেন্ট ID দিয়ে স্থানীয় সিন্থেটিক পুনঃপ্রেরণ করে।
৫. **স্থায়ী নীতি-হোল্ডে** স্থিতিশীল কারণ-কোড দেখা যায়; স্বয়ংক্রিয় নীতি-ওভাররাইড নেই।
৬. **সিন্থেটিক অডিট কার্যক্রমে** নির্বাচিত সিস্টেম কাজ ও কারণ-কোড দেখা যায়—পেলোড বা ব্যবহারকারী শনাক্তকারী নয়।

প্যানেলের শিরোনামে “স্থায়ী” বলা হলেও তা চলমান ডেমোর স্থানীয় স্টোরের আচরণ বোঝায়; এটি উৎপাদন-মানের সংরক্ষণ বা সম্মতি-ব্যবস্থা নয়। ড্যাশবোর্ড প্রসেসে রানটাইম ডেটা সীমাবদ্ধ ও মেমোরিভিত্তিক।

## ৪. ডেমো ডিভাইস ব্যবহার করুন

### সিমুলেটর নিবন্ধন ও নিয়ন্ত্রণ

১. **ডিভাইস ব্যবস্থাপনা** খুলে **সিমুলেটর নিবন্ধন করুন** নির্বাচন করুন। নতুন সারিটি মেমোরিতে থাকা সিন্থেটিক সিমুলেটর; কোনো হার্ডওয়্যার খোঁজা হয় না।
২. **বিস্তারিত দেখুন** দিয়ে সিমুলেটর নির্বাচন করলে তার অবস্থা, স্থানীয় API খসড়া, শেয়ার করা ম্যাপিং প্রিভিউ এবং প্রবাহ দেখা যায়।
৩. **সক্রিয় করুন** সিমুলেটরকে স্থানীয় ডেমো নমুনা পাঠাতে দেয়। **নিষ্ক্রিয় করুন** করলে সেটি আর নমুনা পাঠায় না। কোনোটিই হার্ডওয়্যারে নির্দেশ পাঠায় না।
৪. **নমুনা পাঠান** দিয়ে স্থানীয় পাইপলাইন চালান। ডিভাইসভিত্তিক প্রবাহে উৎস, MediHub-এ গ্রহণ, আউটবক্স এবং প্রসেসের ভেতরের পরীক্ষামূলক গন্তব্য দেখা যায়। তাৎক্ষণিকভাবে দেখতে প্রবাহ হালনাগাদ করুন।
৫. ডিভাইস ক্যাটালগে উদাহরণমূলক বিভাগ আছে, সামঞ্জস্যের তালিকা নয়। **খসড়ায় ব্যবহার করুন** উদাহরণ ধরন নির্বাচন করে; ডিভাইস আবিষ্কার, যাচাই বা সংযোগ করে না।

নিবন্ধন ও সেটিংস অস্থায়ী, সার্ভার পুনরায় চালু হলে মুছে যায়। ডিভাইসভিত্তিক ম্যাপিং প্যানেলটি সবার জন্য শেয়ার করা নিষ্ক্রিয় সিন্থেটিক ম্যাপিং—প্রতিটি বাস্তব ডিভাইসের সংরক্ষিত ম্যাপিং নয়।

### গোপন তথ্যবিহীন API অনুসন্ধান-খসড়া

একটি সিমুলেটর বেছে উদাহরণ ডিভাইস-ধরন, সম্ভাব্য ট্রান্সপোর্ট, পেলোড প্রোফাইল ও পোল ব্যবধান নির্ধারণ করুন। **স্থানীয় খসড়া সংরক্ষণ করুন** শুধু বর্তমান ব্রাউজার পৃষ্ঠা-সেশনে এই মান রাখে। এন্ডপয়েন্ট URL, প্রমাণীকরণ, পাসওয়ার্ড, টোকেন, সার্টিফিকেট বা লাইভ সক্রিয়করণ নেওয়া হয় না। নিষ্ক্রিয় **কানেক্টর সক্রিয় করুন** বোতামটি শুধু তথ্যের জন্য; এটি কানেক্টর চালু করতে পারে না।

বাস্তব ডিভাইস ইন্টিগ্রেশন পরিকল্পনার আগে সঠিক নির্মাতা/মডেল/ফার্মওয়্যার ও প্রোটোকল অনুসন্ধান, অনুমোদিত উৎস-নির্দিষ্টকরণ, প্রতিষ্ঠানের অনুমোদন এবং আলাদাভাবে পর্যালোচিত কানেক্টর ডিজাইন দরকার। উদাহরণ ক্যাটালগকে সমর্থনের দাবি ভাববেন না।

### সিন্থেটিক সারি এক্সপোর্ট

CSV বা JSON বেছে **নির্বাচিত ডিভাইস এক্সপোর্ট করুন** ব্যবহার করে নির্বাচিত সিমুলেটরের সর্বোচ্চ ১২টি সাম্প্রতিক বাছাই করা সিন্থেটিক সারি ডাউনলোড করুন। বর্তমান সিন্থেটিক ড্যাশবোর্ড স্ন্যাপশট থেকে ব্রাউজারে ফাইল তৈরি হয়; কোনো এক্সপোর্ট সেবা বা বাহ্যিক গন্তব্যে পাঠানো হয় না। ফাইলকে পরীক্ষার উপকরণ হিসেবে রাখুন, বাস্তব তথ্য যোগ করবেন না।

## ৫. ম্যাপিং খসড়া পর্যালোচনা ও পরীক্ষা

ম্যাপিং নিয়মে উৎস মেট্রিক ও এককের হুবহু কোড ব্যবহার হয়। নিয়মটি মান অপরিবর্তিত রাখতে পারে অথবা নির্দিষ্ট স্কেল ও অফসেট প্রয়োগ করে নির্ধারিত দশমিক নির্ভুলতা দিতে পারে। প্রিভিউ শুধু সিন্থেটিক; এটি উৎসের একক অনুমান করে না বা নিজে থেকে নিয়ম নির্বাচন করে না।

১. **ডেটা ম্যাপিং**-এ বর্তমান খসড়ার উৎস কোড/একক এবং স্বাভাবিকীকৃত উদাহরণ কোড/একক দেখুন।
২. স্বতন্ত্র হুবহু উৎস মেট্রিক/একক এবং স্বাভাবিকীকৃত উদাহরণ কোড/একক দিয়ে নিয়ম যোগ করুন। ডেমোতে উদাহরণ কোড-সিস্টেম `example.invalid` এবং এককের শব্দভাণ্ডার `UCUM`-এ স্থির।
৩. **ম্যাপিং প্রিভিউ করুন**-এ সিমুলেটর বেছে সিন্থেটিক উৎস কোড, একক ও সংখ্যামান দিন। মিল হুবহু হতে হবে। না মিললে ক্লিনিক্যাল অর্থ অনুমান না করে ম্যাপিং ছাড়া রাখুন।
৪. প্রত্যাশিত আউটপুটসহ সিন্থেটিক **গোল্ডেন টেস্ট ভেক্টর** যোগ করুন। খসড়া বদলানোর পর পরীক্ষা চালান। ফল ম্যাপিং সংস্করণের সঙ্গে যুক্ত; খসড়া বদলালে আগের ফল অচল হতে পারে।
৫. **সংস্করণ ইতিহাস** দিয়ে আগের স্ন্যাপশট তুলনা করুন বা নতুন নিষ্ক্রিয় খসড়া হিসেবে ফিরিয়ে আনুন। মেমোরির ইতিহাসে সর্বোচ্চ ১০০টি সংস্করণ থাকে।

ম্যাপিং সক্রিয় করা নিষ্ক্রিয়। টেস্ট ভেক্টর পাস করা শুধু কোডে থাকা ডেমো উদাহরণ যাচাই করে; এটি ক্লিনিক্যাল যাচাই, পরিভাষা অনুমোদন, ডিভাইস সনদ বা বাস্তব সিস্টেমে লেখার অনুমতি নয়। অতিরিক্ত সীমার জন্য [সিন্থেটিক ম্যাপিং ওয়ার্কবেঞ্চ নোট](SYNTHETIC_MAPPING_WORKBENCH.md) দেখুন।

## ৬. EMR / EMS API পৃষ্ঠা বুঝুন

API পৃষ্ঠাটি পরিকল্পনার অংশ, কানেক্টর কনফিগারেশন নয়:

- **FHIR R4 / EMR** ভবিষ্যৎ পরিকল্পনার লক্ষ্য। কার্ড বিচ্ছিন্ন; বেস URL, পরিচয়-প্রমাণ, নেটওয়ার্ক প্রেরক বা লাইভ সক্রিয়করণ নেই।
- **HL7 v2 / ইন্টারফেস ইঞ্জিন / EMS**-ও ভবিষ্যৎ পরিকল্পনার লক্ষ্য। হোস্ট/পোর্ট ও ট্রান্সপোর্ট/ACK সেটিং নেওয়া হয় না; কার্ড বিচ্ছিন্ন।
- বিদ্যমান রিসিভার ও ত্রুটি-নিয়ন্ত্রণ শুধু প্রসেসের ভেতরের সিন্থেটিক গন্তব্য পরীক্ষা করে। ত্রুটি-পরীক্ষায় পুনঃচেষ্টাযোগ্য ফল, প্রত্যাখ্যান বা হারানো স্বীকৃতি দেখানো যায়, কিন্তু বাস্তব গ্রহণকারী সিস্টেম পরীক্ষা হয় না।

আলাদা বাস্তব ইন্টিগ্রেশন পরিকল্পনার আগে দায়িত্বপ্রাপ্ত প্রতিষ্ঠান ও অনুমোদিত দলকে ইন্টারফেস চুক্তি, রিসোর্স/বার্তা প্রোফাইল, রোগী-প্রসঙ্গের নিয়ম, শনাক্তকারী, স্বীকৃতি, আইডেমপোটেন্সি ও পুনঃচেষ্টার আচরণ, নিরাপত্তা ও গোপনীয়তা নিয়ন্ত্রণ, অনুমোদিত পরীক্ষার এন্ডপয়েন্ট, পর্যবেক্ষণ, সহায়তা এবং পরিবর্তনের দায়িত্বে একমত হতে হবে। এসব বিবরণ এই ড্যাশবোর্ডে দেবেন না।

## ৭. গোপনীয়তা, নিরাপত্তা ও পরিচালনার সীমা

- শুধু সিমুলেটরে তৈরি কৃত্রিম মান ব্যবহার করুন। বাস্তব রোগী বা ডিভাইসের তথ্য অ্যাপ, টেস্ট ফিক্সচার, স্ক্রিনশট, এক্সপোর্ট, লগ বা সোর্স কন্ট্রোলে দেবেন না।
- ইন্টারফেসে গোপন তথ্য দেবেন না। এই ওয়ার্কবেঞ্চে গোপন তথ্য ব্যবস্থাপক বা বাহ্যিক সংযোগ নেই।
- ড্যাশবোর্ডে যাচাইকৃত অপারেটর ভূমিকা, প্রতিষ্ঠান/সাইট-সীমা, উৎপাদন-মানের স্থায়ী কনফিগারেশন বা পরিবর্তন-প্রমাণযোগ্য অডিট ট্রেইল নেই। উৎপাদন নিয়ন্ত্রণ-প্ল্যাটফর্ম হিসেবে প্রকাশ করবেন না।
- local storage-এ শুধু নির্বাচিত ভাষা-পছন্দ রাখা হয়। ডিভাইস API খসড়া JavaScript পৃষ্ঠা-সেশনের map-এ থাকে; সিমুলেটর ও ম্যাপিং রেকর্ড স্থানীয় অ্যাপের মেমোরিতে থাকে। সার্ভার পুনরায় চালু হলে সার্ভার-পাশের ডেমো সেটআপ ও রানটাইম ফিড মুছে যায়।
- ব্রাউজারে ডাউনলোড করা CSV/JSON ব্যবহারকারীর স্থানীয় ডাউনলোড ও ফাইল ব্যবস্থাপনার অধীনে থাকে। পরীক্ষার উপকরণ হিসেবে বিবেচনা করুন।
- প্রকল্পের অন্য event persistence/replay পথে সংরক্ষণের আচরণ আলাদা এবং ইনপুট JSON স্থায়ীভাবে রাখতে পারে। বাস্তব তথ্য দেবেন না; README-এর সিন্থেটিক-শুধু নির্দেশনা অনুসরণ করুন।

## ৮. বাংলাদেশে ডিপ্লয়মেন্ট-প্রস্তুতির তালিকা

MediHub পরিকল্পনার জন্য বাংলাদেশ আবশ্যিক প্রেক্ষাপট, তবে এই সিন্থেটিক প্রিভিউ **বাংলাদেশের কোনো স্বাস্থ্যপ্রতিষ্ঠানে ব্যবহারের জন্য প্রস্তুত নয়**। ভবিষ্যৎ প্রস্তাব এগোনোর আগে প্রতিষ্ঠানভিত্তিক অনুসন্ধান ও অনুমোদনে অন্তত নিচের বিষয়গুলো সমাধান করতে হবে:

- প্রতিটি অংশগ্রহণকারী প্রতিষ্ঠানে ক্লিনিক্যাল, পরিচালন, প্রযুক্তি, গোপনীয়তা, নিরাপত্তা ও ভেন্ডর-দায়িত্বপ্রাপ্ত ব্যক্তি নির্ধারণ;
- সঠিক ডিভাইস মডেল, ফার্মওয়্যার, যোগাযোগ প্রোটোকল, উৎস-পরিভাষা, একক, ক্যালিব্রেশন/গুণমান প্রক্রিয়া ও সহায়তার দায়িত্ব;
- লক্ষ্য EMR/EMS ইন্টারফেস চুক্তি, বার্তা/রিসোর্স প্রোফাইল, রোগী-সংযোগ ও পরিচয়-নিয়ম, ACK/আইডেমপোটেন্সি/পুনঃচেষ্টা আচরণ এবং অনুমোদিত সিন্থেটিক পরীক্ষার পরিবেশ;
- প্রযোজ্য বাংলাদেশি আইন, নিয়ন্ত্রকের নির্দেশ, প্রতিষ্ঠানের নীতি, সম্মতি ও প্রবেশাধিকার, ডেটা কোথায় থাকবে/হোস্টিং, সংরক্ষণকাল, ঘটনা মোকাবিলা ও সীমান্ত-পার ডেটা প্রক্রিয়াকরণের মূল্যায়ন—যোগ্য স্থানীয় অংশীজনদের মাধ্যমে;
- নির্দিষ্ট প্রতিষ্ঠানের সংযোগ সীমা ও পরিচালন পরিবেশ—বিদ্যুৎ/নেটওয়ার্ক বিঘ্ন এবং সহায়তা/জরুরি যোগাযোগসহ;
- ইংরেজি ও বাংলা ব্যবহারযোগ্যতা, বাংলা লিপি রেন্ডারিং, অ্যাক্সেসিবিলিটি, অপারেটর প্রশিক্ষণ এবং ভাষাভিত্তিক নাম/পরিভাষার নিরাপদ ব্যবহার;
- স্বাধীন নিরাপত্তা/গোপনীয়তা মূল্যায়ন, হুমকি-মডেল, প্রমাণীকরণ ও ভূমিকা, এনক্রিপশন, গোপন তথ্য ব্যবস্থাপনা, লগ/সংরক্ষণ, ব্যাকআপ/পুনরুদ্ধার এবং ডিপ্লয়মেন্ট কঠোরকরণ;
- প্রতিষ্ঠানের অনুমোদিত সিন্থেটিক পরীক্ষা, ক্লিনিক্যাল নিরাপত্তা পর্যালোচনা, পরিমাপযোগ্য গ্রহণযোগ্যতা, rollback এবং বাস্তব ডেটা/সংযোগ বিবেচনার আগে স্পষ্ট অনুমোদনসহ ধাপে ধাপে পাইলট পরিকল্পনা।

এটি পরিকল্পনার সহায়ক তালিকা—আইনি পরামর্শ, স্থানীয় সম্মতির ঘোষণা, Bangladesh Core FHIR দাবি বা ডিপ্লয়মেন্ট অনুমোদন নয়। নির্দিষ্ট ডিপ্লয়মেন্টের জন্য দেশভিত্তিক শর্ত ও প্রতিষ্ঠানের চুক্তি যাচাই করতে হবে।

## ৯. সমস্যা সমাধান

| সমস্যা | কী যাচাই করবেন |
| --- | --- |
| নমুনা দেখা যাচ্ছে না | সিমুলেটর নিবন্ধিত ও সক্রিয় করুন, সেটি নির্বাচন করে নমুনা পাঠান। ডিভাইস প্রবাহ হালনাগাদ করুন। |
| ম্যাপিং প্রিভিউতে মিল নেই | উৎস মেট্রিক **এবং** একক খসড়ার সঙ্গে হুবহু মেলে কি না দেখুন; নির্বাচিত সিমুলেটর যাচাই করুন। উদ্দেশ্যকৃত উদাহরণের জন্য সিন্থেটিক টেস্ট ভেক্টর যোগ করুন। |
| ডেলিভারি সারিতে বা ব্যর্থ | ডেলিভারি ও চেষ্টার ইতিহাস দেখুন। বোতাম চালু থাকলেই হাতে পুনঃচেষ্টা করুন; সেটি স্থানীয় সিন্থেটিক পুনঃপ্রেরণ। |
| ডিভাইস বা ম্যাপিং পরিবর্তন হারিয়েছে | সেটআপ অস্থায়ী। সার্ভার পুনরায় চালু হলে সার্ভার-পাশের নিবন্ধন, ম্যাপিং, সংস্করণ এবং রানটাইম ফিড রিসেট হয়; পৃষ্ঠা-সেশন শেষ হলে API খসড়াও হারায়। |
| পৃষ্ঠা হালনাগাদ হচ্ছে না | স্থানীয় সার্ভার চলছে কি না দেখুন এবং পৃষ্ঠা আবার লোড করুন। সংযোগ থাকলে কার্যক্রমের পৃষ্ঠা স্বয়ংক্রিয়ভাবে হালনাগাদ হয়। |
| বিভিন্ন কম্পিউটারে বাংলা লেখা আলাদা | ফন্ট ও ব্রাউজার রেন্ডারিং ভিন্ন হতে পারে। UI বাংলা ফন্টকে fallback হিসেবে নির্ধারণ করে, ফন্ট ডাউনলোড করে না; লক্ষ্য ডিভাইসে বাংলা-সমর্থিত ফন্ট ও ব্রাউজার যাচাই করুন। |
| EMR/EMS নিয়ন্ত্রণ ব্যবহার করা যাচ্ছে না | এটি ইচ্ছাকৃত। API কার্ডগুলো বন্ধ পরিকল্পনা, লুকানো সংযোগ সেটআপ নয়। |

## ১০. পরিভাষা

- **সিন্থেটিক ডেটা:** তৈরি ডেমো মান, যা কোনো ব্যক্তি, রোগী, বাস্তব ডিভাইস বা ক্লিনিক্যাল পরিমাপকে উপস্থাপন করে না।
- **সিমুলেটর:** একই প্রসেসের ডেমো উৎস, যা ওই কৃত্রিম মান পাঠাতে পারে।
- **আউটবক্স:** রিসিভারে পাঠানোর আগে/সময়ে ডেলিভারি অনুরোধ ও চেষ্টার স্থানীয় রেকর্ড। এখানে রিসিভার একই প্রসেসে চলে।
- **আইডেমপোটেন্সি:** পুনরাবৃত্ত স্থিতিশীল ইভেন্ট ID শনাক্ত করা, যাতে ডুপ্লিকেট পাঠে দ্বিতীয় স্বতন্ত্র পরীক্ষামূলক রসিদ তৈরি না হয়।
- **ম্যাপিং খসড়া:** সিন্থেটিক উৎস কোড/একক থেকে উদাহরণ স্বাভাবিকীকৃত কোড/এককে রূপান্তরের নিষ্ক্রিয়, অস্থায়ী হুবহু-মিল নিয়ম।
- **FHIR R4 / HL7 v2:** ভবিষ্যৎ ইন্টারফেস-পরিকল্পনার লক্ষ্য হিসেবে উল্লেখ করা মান; এই ড্যাশবোর্ডে কোনোটিই সংযুক্ত নয়।
